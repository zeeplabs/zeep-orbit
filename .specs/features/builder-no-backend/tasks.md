Gate: Go `go build ./... && go vet ./... && gofmt -l cmd internal && go test -p 1 -parallel 4 ./...`; UI `npx tsc -b`, `npm test`, `npm run build`, i18n JSON valid. Template: `npm ci && npx tsc -b && npm run build` in each template.

Status 2026-11-25: T1 to T10 are done (T2 to T8 merged as #66 to #72). T9 found that the "No backend" default sends every app prompt to a static plan, so the chat home default went back to "New backend" (see validation.md). T11 (phase 2, now the most valuable part: attach a backend to the session) are open. Order matters: layers 1 and 2 are invisible to users; layer 3 changes the default and ships last. Everything stays on beta until the maintainer authorizes `latest`.

  - **T11d-1 (done 2026-11-27)** Builder side: `builder/templates/backend-overlay` (manifest, SDK files, guide; also adds `react-router-dom`, which the default guide assumes), `Dockerfile.builder` line, `Workspace.ApplyOverlay` (conflicts found before any write, ordered `package.json` merge, idempotent by opID), route `POST /v1/sessions/{id}/overlay`, `sandbox.ApplyBackendOverlay` and `IsOverlayConflict`, equality test with the default template. The overlay name is refused as an Init template.
  - **T11d-2 (done 2026-11-27)** Worker: `runAttach` in `internal/agent/attach.go` (overlay, commit, snapshot, `Deps.AttachBackend`, install and build, `backend_attached` event; compensation by `Builder.Revert` to the head the session had, which also drops an uncommitted tree, and snapshots it). `Deps.AttachBackend` (`agent.AttachFunc`) is set by `BuilderHandler.attachBackend` through `BuilderHandlerConfig.SetAttachBackend` / `BuilderRuntime.SetAttachBackend` (the runtime is built before the handler). The callback runs as the session owner, creates the app for mode new, re-checks access for mode existing, removes a created app when the conditional update fails, and is idempotent for a resumed turn (it returns the app an earlier attempt attached). Codes: `overlay_conflict`, `attach_failed`, `attach_unavailable`, `commit_failed`, `workspace_lost`. A failed install or build does not fail the turn. `revertBuild` was split into `buildStep`, shared with the attach turn.
  - **T11d (original text)** Builder and worker: `backend-overlay` directory and `Dockerfile.builder` line, builder route `POST /v1/sessions/{id}/overlay` (collision check, dependency merge), `sandbox.Overlay`, `runAttach` with compensation, `Deps.AttachBackend`. Equality test with the default template.
  - **T11e (done 2026-11-28)** API: `POST /dashboard/api/builder/sessions/{id}/backend` (`BuilderHandler.AttachBackend`, `internal/dashboard/builder_attach.go`, route with the AI chat limiter). Body `{mode: new|existing, app_id?}`. 202 with the `attach_backend` turn; 400 for a bad body, mode `none`, `app_id` with mode new, or a company-template session (the overlay targets the built-in template); 404 for a missing session or an app the caller cannot see; 409 when the session already has a backend or a turn is active (a pending plan card is ended by the store transaction); 503 when the builder is unavailable. The new app name is derived from the session title and is only recorded in the payload (the worker creates the app). Audit `builder.session.backend.attach` with `mode`, `turn_seq` and, for existing, `app_id`. 8 handler tests against Postgres.
