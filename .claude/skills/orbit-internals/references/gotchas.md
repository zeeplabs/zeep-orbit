# Gotchas and invariants flagged directly in code

These are comments in production (non-test) code that cite AGENTS.md or a past incident explicitly — they exist because someone got burned. Treat them as load-bearing, not stylistic.

- **Schema name derivation** (`internal/dashboard/apps_store.go:451`): never hardcode `"app_" + name` or any other pattern — only `strings.ReplaceAll(appName, "-", "_")` is correct. Shipped to production once as a real bug.
- **RLS is a one-way ratchet** (`internal/dashboard/apps_store.go:640-648`, tagged `RLSP-08`/`RLSP-02` in comments): switching a table to `rls="policy"` always (idempotently) enables native Postgres RLS; there is no code path that disables it again once on. This is a deliberate fail-closed guarantee — don't add a "disable RLS" path without understanding why it doesn't exist.
- **`enum` is not a native Postgres type** (`internal/provisioner/table.go:44-48`): it's `TEXT` + a `CHECK` constraint, on purpose, as its own explicit `switch` case in `pgType`. A missing `case` here for a numeric-like type was the historical root cause of a production schema-drift bug (D-228 in project history) — 7 columns configured as `numeric` were physically `TEXT` for over a month. Never let a column type fall through to a default case silently.
- **No in-memory state keyed by process** (referenced around `internal/dashboard/pat_store.go:95`, `internal/dashboard/oauth_server.go:40`, `internal/provisioner/provisioner.go:547`): PATs, sessions, OAuth state are always resolved against Postgres or a signed stateless token (HMAC-SHA256 + `exp`), never cached in a process-local map. This service runs multiple replicas behind a non-sticky load balancer — anything in-memory that a later request depends on will randomly fail depending on which pod handles it.
- **MCP transport runs `Stateless: true`** (`internal/mcpserver/server.go:21-28`) for the same non-sticky-load-balancer reason above — don't "optimize" this to stateful mode without re-solving that problem first.
- **Never leak `err.Error()` into a tool/HTTP response** (AGENTS.md §4, cited literally at `internal/mcpserver/tools.go:6,41,51,172,742`, `webhook_handler.go:448`, `policy.go:96`, and 14 production files total): log the real error server-side, return a fixed generic message. `provisioner.ValidationError`/`TypeChangeError` are the documented exceptions because they're safe to expose — that's the exception, not a precedent for exposing other error types.
- **`UpdateApp`'s REST handler does not reconcile table schema** (removed deliberately, D-228): saving a Login/Storage/API-tab field must never call `Provisioner.Apply`, which walks every table in the app. If you need to provision something on an app-level toggle flip, add a narrowly-scoped `Ensure*Tables`-style method (see `EnsureAuthTables`/`EnsureStorageTables`, added specifically to close the gap `Apply`'s removal opened for auth/storage tables — D-232) rather than reintroducing the full reconciliation call.
- **Partial-update endpoints merge on absent keys.** A frontend form that lets a user clear a field must send that field's key explicitly with an empty value/array — omission is read as "don't touch this field" (see `mergeProviderConfig` in `internal/dashboard/auth_providers_store.go` for the established pattern before adding a new mergeable config surface).
